# 实验3说明指南

本指南说明 `experiment3_function_calling` 中各文件夹和主要文件的用途。
实验的功能实现、测试结果和问题分析见同目录下的
`实验3总结.md`。

## 1. 目录总览

```text
experiment3_function_calling/
├─ src/
│  └─ tests/
├─ docs/
├─ results/
├─ logs/
│  └─ basic/
├─ .venv/
├─ README.md
├─ requirements.txt
├─ .gitignore
└─ .gitkeep
```

## 2. 根目录文件

| 文件或目录 | 说明 |
| --- | --- |
| `src/` | 实验的全部 Python 实现、Schema、Agent 和运行入口 |
| `docs/` | 原始实验说明、实验总结和使用指南 |
| `results/` | 端到端测试的汇总结果 |
| `logs/` | Agent 每次运行生成的调用日志 |
| `.venv/` | 本地 Python 3.12 虚拟环境，包含已安装的第三方依赖 |
| `README.md` | 快速运行命令和目录入口 |
| `requirements.txt` | 锁定的直接依赖版本 |
| `.gitignore` | 忽略虚拟环境、Python 缓存和普通日志文件 |
| `.gitkeep` | 早期占位文件，不参与实验运行 |
| `__pycache__/` | Python 自动生成的字节码缓存，可以删除或重新生成 |

## 3. `docs` 文件夹

| 文件 | 说明 |
| --- | --- |
| `实验3 会议时间查询工具（Function Calling）.docx` | 课程提供的原始实验说明和验收要求 |
| `实验3总结.md` | 基础实验的完整总结，包括架构、工具、Prompt、测试结果和限制 |
| `实验3说明指南.md` | 当前文件，用来说明目录和文件职责 |

提交实验时，实验总结和原始说明都在同一个文件夹中，便于查阅。

## 4. `src` 文件夹

### 4.1 配置和模型入口

| 文件 | 说明 |
| --- | --- |
| `config.py` | 定位实验根目录，读取上一级 `.env`，校验 API 配置，并创建 OpenAI 客户端 |
| `check_environment.py` | 检查 Python 版本、配置文件、IANA 时区和客户端配置 |
| `first_turn.py` | 构造 System Prompt，完成一次模型调用并整理首轮工具调用 |

`config.py` 从上一级 `week1_llm_lab/.env` 读取：

```text
OPENAI_API_KEY
OPENAI_BASE_URL
MODEL_NAME
```

`.env` 不会复制到实验目录，API Key 也不会写入日志。

### 4.2 Python 工具

| 文件 | 说明 |
| --- | --- |
| `tools.py` | 提供当前时间、日期差值、会议截止日期和时区转换四个工具 |
| `tool_schemas.py` | 定义发送给模型的 Function Calling JSON Schema |
| `dispatcher.py` | 实现工具白名单、JSON 参数解析、参数校验和本地函数调用 |

工具名和数据流如下：

```text
tool_schemas.py
  → 模型生成 tool_calls
  → dispatcher.py 校验并调度
  → tools.py 执行本地 Python 函数
  → 结构化结果返回模型
```

### 4.3 Agent 和日志

| 文件 | 说明 |
| --- | --- |
| `agent.py` | 完整的“模型调用—工具执行—结果回传—模型回答”多轮循环 |
| `call_logger.py` | 为每次 Agent 运行创建 UTF-8 JSONL 调用日志 |
| `run_basic_tests.py` | 连续执行六组基础问题，校验工具链并写出测试结果 JSON |

`agent.py` 支持一次响应中的多个工具调用，并会限制模型与工具交互的最大轮数。
工具只能通过 `dispatcher.py` 中注册的白名单执行。

### 4.4 `src/tests` 文件夹

`src/tests` 存放不调用真实模型的自动化测试。

| 文件 | 说明 |
| --- | --- |
| `__init__.py` | 使测试目录成为可导入的 Python 包 |
| `test_tools.py` | 测试四个工具、非法日期、非法时区和夏令时边界 |
| `test_dispatcher.py` | 测试白名单、JSON 解析、缺失参数、错误类型和多余参数 |
| `test_agent.py` | 使用模拟模型测试多轮工具调用、`tool_call_id` 和日志写入 |

运行全部测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s src\tests -t src -v
```

## 5. `results` 文件夹

| 文件 | 说明 |
| --- | --- |
| `basic_test_results.json` | 最近一次六组基础端到端测试的汇总结果 |

该文件包含：

- 测试执行时间；
- 通过数量；
- 用户问题和最终回答；
- 模型轮数和工具调用次数；
- 每项自动校验结果；
- 对应日志的文件路径。

结果文件由 `src/run_basic_tests.py` 自动生成，不建议手工修改。

## 6. `logs` 文件夹

`logs` 保存 Agent 的运行证据。每次运行生成一个独立 `.jsonl` 文件，文件名格式为：

```text
run_YYYYMMDDTHHMMSS_<run_id>.jsonl
```

| 目录 | 内容 |
| --- | --- |
| `logs/` | 手工运行单个问题或开发调试产生的日志 |
| `logs/basic/` | 通过 `run_basic_tests.py` 产生的六组验收日志 |

每行是一个 JSON 事件，主要事件包括：

- `run_start`：用户问题、模型名称和开始时间；
- `model_request`：模型调用轮次；
- `model_response`：模型内容和工具请求；
- `tool_call`：工具名、参数、耗时、状态和结果；
- `runtime_error`：运行异常；
- `run_end`：最终回答、总轮数和总工具次数。

由于重复测试会生成新文件，`logs/basic` 中的文件数量可能多于六个。一次完整的
基础测试通常会产生六份日志，文件名中的时间可作为一次测试批次的标识。

## 7. `.venv` 文件夹

`.venv` 是本地虚拟环境，不是实验源代码。其内部包含：

- 当前 Python 解释器的虚拟环境配置；
- OpenAI SDK；
- `python-dotenv`；
- `tzdata`；
- 依赖包及其运行时文件。

通常不需要逐个查看 `.venv` 中的文件。需要恢复环境时，可删除并重建该文件夹，
然后执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 8. 常用命令

以下命令均在 `experiment3_function_calling` 根目录执行。

检查环境：

```powershell
.\.venv\Scripts\python.exe src\check_environment.py
```

运行六组完整验收：

```powershell
.\.venv\Scripts\python.exe src\run_basic_tests.py
```

运行单个问题：

```powershell
.\.venv\Scripts\python.exe src\agent.py "ICCBDA 2027 的截稿日期还有多久？"
```

运行自动化测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s src\tests -t src -v
```

## 9. 文件维护建议

- 源代码放在 `src`，不要把新的实现文件放回根目录。
- 测试文件放在 `src/tests`，文件名以 `test_` 开头。
- 手工运行日志和批量验收日志分别使用 `logs` 与 `logs/basic`。
- 修改运行脚本后，将结果继续写入 `results`，避免在根目录生成大量结果文件。
- `__pycache__` 和 `.pyc` 是自动缓存，不属于实验源码。
- 不要把父目录 `.env` 复制到实验目录，也不要在日志或报告中输出 API Key。
