# 实验3：会议时间查询工具（Function Calling）— 实验报告

> 基础实验（不含进阶挑战）。完整源代码见 `main.py`，测试输出见 `results.json`。

## 一、实验目的

理解 Function Calling 完整闭环：**模型选择工具 → 程序执行工具 → 工具结果回传模型 → 模型组织答案**。核心要点：
- 模型只负责「决定调用哪个工具、传什么参数」，**不**直接计算结果；
- 真实计算由本地 Python 函数完成，结果再回传给模型；
- 程序对工具名称与参数做白名单校验，禁止执行模型生成的任意代码。

## 二、运行环境

- Python 3.11（虚拟环境 `.venv`）；时间与时区依赖 `zoneinfo`，在 Windows 上需安装 `tzdata`
- `openai`（兼容接口）、`python-dotenv`
- 模型：`deepseek-flash`

## 三、Python 工具实现（4 个）

| 工具 | 功能 | 关键实现 |
|------|------|----------|
| `get_current_time(timezone)` | 查询指定 IANA 时区当前时间 | `datetime.now(ZoneInfo(tz))` |
| `days_until(target_date)` | 计算目标日期距今天数 | `date.fromisoformat` 求差 |
| `get_conference_deadline(name)` | 查询模拟会议数据库 | 字典查找，未找到返回错误 |
| `convert_timezone(dt, src, tgt)` | 时区转换（自动处理夏令时） | `astimezone(ZoneInfo)`，绝不用固定加减小时 |

会议数据库（基础实验用字典实现）：
```python
CONFERENCE_DATA = {
    "ICCBDA 2027": {
        "submission_deadline": "2027-02-15",
        "conference_start": "2027-05-21",
        "conference_end": "2027-05-23",
    }
}
```

## 四、Function Calling 闭环流程

```
用户问题
   │
   ▼
将「问题 + 工具声明(tools)」发送给模型
   │
   ▼
模型返回 tool_calls？（否 → 直接生成最终回答）
   │ 是
   ▼
读取工具名 + JSON 参数
   │
   ▼
白名单映射到本地函数并执行（禁止 eval / 任意代码）
   │
   ▼
工具结果以 role=tool 消息回传模型
   │
   ▼
模型根据真实结果组织最终自然语言回答
```

## 六、测试结果（Q1–Q6）

| 编号 | 用户问题 | 预期工具 | 实际工具调用 | 结果 |
|------|----------|----------|--------------|------|
| Q1 | 现在新加坡几点？ | get_current_time | get_current_time(Asia/Singapore) | 返回新加坡当前时间 |
| Q2 | 现在纽约几点？ | get_current_time | get_current_time(America/New_York) | 返回纽约当前时间 |
| Q3 | 2027年2月15日距离今天还有多少天？ | days_until | days_until(2027-02-15) | 返回剩余天数（今天 2026-11-11 → 96 天） |
| Q4 | ICCBDA 2027 的截稿日期还有多久？ | get_conference_deadline + days_until | 先查会议库得 2027-02-15，再 days_until | 返回 96 天（真实 API 验证一致） |
| Q5 | 东京明天上午9点对应北京时间几点？ | convert_timezone | convert_timezone(次日09:00, Asia/Tokyo, Asia/Shanghai) | 东京 09:00 → 北京 08:00（冬令时差 1 小时） |
| Q6 | 查询不存在的会议 XYZ 2027 的截稿日期。 | get_conference_deadline（未找到） | get_conference_deadline(XYZ 2027) | 返回 `Conference not found`，模型如实告知未找到 |

**工具调用链示例（Q4，真实 API 验证）**
```
🔧 get_conference_deadline({'conference_name': 'ICCBDA 2027'})
   -> {"submission_deadline": "2027-02-15", "conference_start": "2027-05-21", ...}
🔧 days_until({'target_date': '2027-02-15'})
   -> {"today": "2026-11-11", "days_remaining": 96}
最终回答：ICCBDA 2027 的投稿截止日期是 2027-02-15，距离今天还有 96 天。
```

**时区转换示例（Q5）**
```
东京 2026-11-12 09:00 (+09:00)  →  北京 2026-11-12 08:00 (+08:00)，offset = -1.0h
```

## 七、安全与异常处理

- **白名单执行**：`FUNCTIONS` 字典显式登记 4 个工具，模型返回的其他名称一律拒绝（`未知工具`）；
- **参数校验**：`days_until` 校验日期格式、`get_current_time`/`convert_timezone` 校验 IANA 时区名（捕获 `ZoneInfoNotFoundError`）；
- **不存在的会议 / 无效输入**：工具返回结构化错误信息，模型据此如实回答，绝不伪造成功结果；
- **相对日期**：`convert_timezone` 支持 `tomorrow` / `today` 自动展开为具体日期，避免模型或用户漏写日期。

## 八、实验总结

本实验完整实现了 Function Calling 的「模型决策—程序执行—结果回传—答案组织」闭环。相比让模型直接「心算」日期或时差，由本地函数计算保证了结果的确定性与可审计性。测试覆盖单工具、多工具串联（Q4）、时区转换（Q5）与异常情况（Q6），验证了工具选择、参数生成与异常处理的可靠性。
