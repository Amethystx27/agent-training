## 使用顺序

1. 阅读`第二周实验指导书-学生用.docx`。
2. 按照培训通知创建Python环境并安装依赖。
3. 复制`.env.example`为`.env`，填写教师发放的个人接口配置。
4. 复制`代码框架/`到自己的项目目录。
5. 将`学生资料/会议材料/`中的8份DOCX复制到项目的`data/raw/`。
6. 使用`学生资料/解析样例/`测试DOCX表格和PDF逐页文本解析。
7. 完成`src/rag.py`中的TODO。
8. 运行实验1、实验2和实验3，保存原始结果和报告。

## 实验边界

- 只将`学生资料/会议材料/`中的8份DOCX作为知识库输入。
- 不要将代码、README、测试问题、`.env`或自己编写的答案文件放入向量知识库。
- 所有会议、机构、地点、费用和联系人均为教学虚构信息。
- `example.org`域名仅作示例，不访问、不投稿、不付款。
- 不得提交`.env`、真实API Key或包含密钥的日志。
- 不得加载同学、用户上传或来源不明的FAISS索引。

`学生资料/解析样例/`只用于验证解析器，不属于正式8份会议知识库。不要将这些样例默认复制到`data/raw/`，否则会改变正式语料的文件数和测试基线。

## 提交要求

- 完整源码及README；
- `requirements-lock.txt`和`.env.example`；
- 8份原资料清单及哈希；
- 解析统计、chunk样例和索引重建命令；
- Prompt、模型和参数配置；
- 28题原始响应及逐题评价；
- 至少两组`chunk_size`或`top_k`对比；
- 来源展示和拒答结果；
- 实验报告和Git提交记录。

代码框架中的TODO是有意保留的教学任务。当前发放包不包含完整参考答案或成品系统。
