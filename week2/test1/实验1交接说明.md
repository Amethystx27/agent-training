### 5.2 FAISS索引

索引目录：

```text
index/
```

文件组成：

```text
index.faiss
index.pkl
manifest.json
```

索引统计：

| 指标 | 结果 |
|---|---:|
| 向量数 | 33 |
| 来源文件数 | 8 |
| 向量维度 | 1024 |
| 距离策略 | Euclidean Distance |
| 可信本地索引标记 | 是 |

`manifest.json`记录8份原始文件的SHA-256、Embedding模型、向量维度、chunk参数和可信索引标记。加载索引时会重新核对原始文件是否存在以及哈希是否一致。

因此：

1. 不得只复制`index/`而遗漏`data/raw/`。
2. 不得加载来源不明的`index.pkl`。
3. 修改任何原始文件后必须重新执行`prepare`和`index`。
4. 更换Embedding模型或维度后必须重建索引。
5. 检索距离只表示向量空间中的距离，不是答案正确率或置信度。

索引清单见[manifest.json](index/manifest.json)。由于`index/`被`.gitignore`忽略，如果实验2在全新环境中运行，必须根据8份原始资料和相同Embedding模型重新构建索引。

## 6. 现有代码接口

主要实现位于：

```text
src/rag.py
```

已经实现并可复用的接口：

```python
load_documents(path) -> list[Document]
split_documents(docs) -> list[Document]
build_index(chunks, embedding) -> VectorStore
retrieve(question, k=4) -> list[Document]
```

### 6.1 检索接口

当前检索入口为：

```python
retrieve(
    question,
    k=4,
    index_dir=DEFAULT_INDEX_DIR,
    embedding=None,
)
```

如果未传入`embedding`，函数会创建`CourseEmbeddings`并读取环境配置。返回的每个`Document`包含：

```text
page_content
metadata
metadata.retrieval_score
```

其中`metadata`保留来源、章节、段落范围、chunk ID、文档版本和文件哈希等定位信息。

实验2应直接使用这些实际检索结果构造证据上下文，不得让LLM自行编造文件名、chunk ID或原文引用。

### 6.2 尚未实现的实验2接口

当前`answer()`仍为占位接口：

```python
def answer(question: str) -> dict:
    raise NotImplementedError(...)
```

实验2需要实现返回结构：

```python
{
    "answer": str,
    "citations": [
        {
            "chunk_id": str,
            "source": str,
            "locator": str,
            "quote": str,
        }
    ],
    "needs_human_review": bool,
}
```

约束：

1. `citations`只能引用本次真实检索得到的chunk。
2. `quote`必须能在对应chunk原文中找到。
3. `locator`优先使用DOCX的`section`和`paragraph_range`，PDF使用页码。
4. 金额计算必须展示公式，并引用输入金额对应的证据。
5. 资料无法支持答案时应返回“资料未提供/需人工确认”，不能编造。

## 8. 常用命令

解析资料并重新生成chunks：

```powershell
.\.venv\Scripts\python.exe -m src.rag prepare
```

构建或重建索引：

```powershell
.\.venv\Scripts\python.exe -m src.rag index
```

检索单个问题：

```powershell
.\.venv\Scripts\python.exe -m src.rag query "学生作者早鸟价格是多少？" --k 4
```

运行测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

仅在以下情况下执行重建：

1. 8份原始DOCX被修改或替换。
2. chunk切分参数或chunk内容发生变化。
3. Embedding模型、服务或向量维度发生变化。
4. 索引清单或索引文件损坏。
