# 实验2总结报告

## 1. 实验名称

第二周 RAG 企业知识库开发：检索与 RAG 问答链。

## 2. 实验目标

在实验1的FAISS知识库基础上，实现以下在线链路：

```text
用户问题
→ 子查询规划
→ Retriever召回证据
→ 合并去重
→ 构造[S1]编号上下文
→ Prompt
→ LLM生成
→ 结构化引用映射与原文校验
→ answer/citations/needs_human_review
```

实验2重点区分三类问题：

1. 必要证据没有被召回。
2. 证据已经召回，但上下文不足以回答问题。
3. 证据充分，但模型误读、计算错误或生成虚假引用。

## 3. 实现文件

| 文件 | 作用 |
|---|---|
| `src/rag_qa.py` | 实验2核心实现与CLI |

`deepseek-flash`是推理型模型，短输出预算可能全部被推理内容消耗并返回空正文。本实现为回答预留3500 tokens，并对空正文明确报错，不会把空响应当作答案。

## 5. 检索与问答实现

### 5.1 查询规划

原始问题首先执行一次top 4检索。对于以下组合问题，增加子查询：

- 注册费和住宿同时出现时，分别检索费用身份条件和住宿价格条件。
- 会议发票和住宿同时出现时，分别检索注册费发票范围与住宿发票申请方式。
- 学生听众询问费用时，增加学生听众身份与价格适用条件查询。
- 出现“最终、最新、更正、延期、替代、改为”时，增加更正通知中的最终有效信息查询。

各子查询的召回结果按`chunk_id`去重，并在每个证据上记录它由哪些子查询召回。该方法用于覆盖Q9、Q11和Q17等跨文档题，不调用教师标准答案。

### 5.2 证据上下文

每条证据按以下格式提供给模型：

```text
[S1]
来源：02_注册须知及费用.docx
章节：费用表
定位：费用表，段落5-6
文档版本：current
原文：……
```

上下文默认最多6000字符。超限时按完整证据块依次装入，并在最后一块截断，避免无界拼接。

### 5.3 结构化输出

模型只被要求返回：

```json
{
  "answer": "带[S1]编号的回答",
  "citations": [
    {
      "evidence_id": "S1",
      "quote": "原文片段"
    }
  ],
  "needs_human_review": false
}
```

模型不直接生成文件名、chunk ID或定位信息。程序根据`evidence_id`映射实际检索结果，再返回：

```json
{
  "answer": "...",
  "citations": [
    {
      "chunk_id": "...",
      "source": "02_注册须知及费用.docx",
      "locator": "费用表，段落5-6",
      "quote": "..."
    }
  ],
  "needs_human_review": false
}
```

### 5.4 引用校验

引用执行以下检查：

1. `evidence_id`必须属于本题实际召回的证据。
2. `quote`必须能在对应chunk原文中找到。
3. 模型改变换行或空白时，程序按非空白字符定位，并返回源文中的精确连续切片。
4. 答案中的`[Sx]`必须对应已有证据编号。
5. 无有效引用、上下文被截断、响应为空或无召回时，设置`needs_human_review=true`。

该检查可以阻止模型自行编造文件名和引用，但“引用原文是否在语义上完整支持结论”仍需实验3进一步评价。

## 6. 六题实际运行结果

运行命令：

```powershell
.\.venv\Scripts\python.exe -m src.rag_qa batch data\experiment2_questions.json --output results\experiment2\rag_answers.json --top-k 4
```

| 题号 | 类型 | 结果 | 引用数 | 人工复核 | 耗时 |
|---|---|---|---:|---|---:|
| Q1 | 直接 | 2027年6月18至20日，澄湾市云帆学术中心 | 2 | 否 | 3.073秒 |
| Q3 | 易混 | 全文3月27日18:00；摘要仍为3月10日18:00 | 3 | 否 | 4.697秒 |
| Q9 | 跨文档 | 学生听众5月2日到账按非作者听众常规价600元 | 3 | 否 | 2.879秒 |
| Q11 | 多跳 | 注册1600元 + 住宿900元 = 2500元 | 7 | 是 | 17.502秒 |
| Q14 | 易混 | 智能会务分会最终在A203 | 2 | 否 | 2.557秒 |
| Q17 | 跨文档 | 会议发票仅含注册费；住宿发票向学舍申请 | 2 | 否 | 4.140秒 |

整体批处理耗时34.848秒，六题均成功执行，0个执行错误。

Q11回答同时指出两个前提：两人确实符合学生作者资格并在早鸟截止前到账，以及房间库存不保证。由于题目提供了假设条件，数学模型能够正确计算2500元；但真实个人资格、到账状态和房间库存无法由公开知识库确认，因此`needs_human_review=true`是合理的。

## 10. 当前限制

1. 本次只运行实验2指定的首轮六题，尚未执行实验3的28题和拒答统计。
2. 当前引用校验只验证“引用存在且来自真实chunk”，尚未自动判断引用是否完整蕴含每一句结论。
3. 查询拆分采用确定性规则，能够覆盖当前六题和典型费用/住宿/更正问题，但复杂自然语言仍需更通用的规划。
4. 尚未比较两组chunk_size或top_k参数，也未计算完整事实正确率、证据覆盖率和拒答正确率。
5. 当前环境为Python 3.12.10，与指南Python 3.11存在偏差。
6. `deepseek-flash`的推理内容可能占用较多输出token，Q11单题使用3188 completion tokens。
7. 实验2首轮可以回答公开政策，但不能确认个人付款、录用资格、房态等实时或私有事实。
