# 实验1总结报告

## 1. 实验名称

第二周 RAG 企业知识库开发：会议文档解析与向量知识库

## 2. 实验目标

完成会议资料从原始文件到可持久化向量知识库的离线处理链路：

```text
会议资料
→ 文档解析
→ 文本规范化
→ 按章节和长度切分
→ 生成带来源定位的chunk
→ Embedding
→ FAISS入库与持久化
→ 重新加载
→ 相似度检索
```

实验1不包含LLM问答、引用校验和无依据拒答，这些属于实验2和实验3。

## 5. 实现内容

### 5.1 文档解析

- DOCX按正文中的实际顺序读取标题、段落和表格。
- 表格转换为保留表头和值的检索文本。
- 当前资料没有Word表格，表格能力通过合成DOCX测试验证。
- PDF使用`pypdf`逐页提取文本，页码从1开始。
- 空PDF页会记录OCR需求，不会被静默当作有效文本。
- 文件损坏或整体无法提取文本时，会产生文件级错误并中止，不会静默跳过。

### 5.2 文本规范化和章节识别

- 清除控制字符并合并多余空白。
- 保留金额、币种、日期、否定条件和更正关系。
- 根据Word标题样式和编号标题识别章节。
- DOCX使用真实段落范围定位，不伪造页码。
- 08更正通知的文档版本统一识别为`v2`，其他文档为`current`。

### 5.3 Chunk切分

- 初始参数为`chunk_size=600`、`chunk_overlap=100`。
- 优先按章节、段落、中文句号、分号和逗号切分。
- 每个chunk包含来源、文档编号、章节、定位、文档版本和文件哈希。
- `chunk_id`由来源、文件哈希、章节、定位、序号和文本确定性计算，不使用随机UUID。

### 5.4 Embedding

- 使用OpenAI兼容接口调用真实Embedding服务。
- 每批最多发送10条文本。
- 校验返回数量、返回顺序、向量维度和非有限数值。
- 记录Embedding模型和维度，生成模型变化后会拒绝加载旧索引。

### 5.5 FAISS索引

- 使用FAISS保存33个chunk向量。
- 生成`manifest.json`，记录文件哈希、模型、维度、chunk参数和距离策略。
- 只加载带可信标记的自产本地索引。
- 加载索引时重新校验8份原始文件哈希；资料修改后必须重建。
- 索引使用欧氏距离，分数越小表示距离越近；分数不能直接解释为答案置信度。

## 11. 需要注意的地方

### 11.1 Embedding批次限制

当前服务一批最多接受10条文本。默认批次过大时服务返回HTTP 400，代码已改为10。更换供应商时应先查看批次限制。

### 11.2 检索分数不是置信度

当前索引使用欧氏距离，数值越小越接近。它只表示向量距离，不代表答案正确概率，也不能用来判断证据是否充分。

### 11.3 更换模型必须重建索引

不同Embedding模型或不同维度不能混用。加载索引时会检查模型标识和维度，不一致时拒绝使用。

### 11.4 修改原文件后必须重建

加载索引时会核对原始文件哈希。文件发生变化后，旧索引会被拒绝，应重新执行：

```powershell
.\.venv\Scripts\python.exe -m src.rag prepare
.\.venv\Scripts\python.exe -m src.rag index
```

### 11.5 索引文件不要跨环境分发

FAISS的`index.pkl`反序列化具有安全风险。当前程序只允许加载带可信标记的本地索引。不得加载同学、用户上传或来源不明的索引。

### 11.6 密钥不能提交

真实配置只放在`.env`中，该文件已被Git忽略。`.env.example`必须保持空占位。若真实密钥曾进入可提交文件或对外发送，应更换密钥。

### 11.7 索引可重建但不必提交

当前项目`.gitignore`忽略`index/`。提交源码、资料和依赖锁后，应使用相同Embedding模型重新构建索引。

### 11.8 PDF、表格和规模限制

- OCR不在本周要求内。
- 正式资料没有PDF和Word表格，相关能力仍需用补充样本验收。
- 当前只有8份小规模资料，检索指标不能代表真实企业知识库。
