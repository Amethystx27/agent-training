# 实验1：会议通知智能信息提取 —— 实验报告

**提交人**：zp123456-zp（分支 ZhaoPan）
**实验环境**：Python 3.11.16 + openai SDK + pydantic v2；模型 deepseek-flash（兼容 OpenAI 接口）
**运行入口**：`python main.py <通知文件> [--prompt-version 1|2]`，自测 `python main.py --mock`

---

## 一、实验目的

验证“大语言模型 + 结构化约束（JSON Schema + 程序校验）”在会议通知信息抽取任务上的可行性与稳定性，重点考察：
1. 模型能否稳定输出**合法 JSON**；
2. 能否正确处理**缺失字段（以 null 表示，不臆造）**；
3. 能否提取**多类别 / 多收费阶段**的注册费用；
4. 不同 **Prompt 设计**对抽取质量的影响。

---

## 二、方法

### 2.1 抽取流程
```
会议通知文本 → 大模型(强制 response_format=json_object) → 原始 JSON 字符串
            → 正则容错提取最外层 {} → json.loads → Pydantic(MeetingInfo) 校验
            → 输出规范 JSON
```
- **字段**：conference_name / date / location / theme / submission_deadline / registration_fees（费用数组）
- **硬性规则**：缺失信息填 `null`；日期统一 `YYYY-MM-DD`；`registration_fees` 必须为数组；仅输出 JSON。
- **程序校验**：Pydantic 校验字段完整性、日期格式（`^\d{4}-\d{2}-\d{2}$` 且为真实日期）、金额类型（float）。

### 2.2 两个版本的 Prompt（核心对比变量）
- **V1（基础版）**：字段清单 + 基础规则，措辞简洁。
- **V2（改进版）**：在 V1 基础上（1）显式要求多档费用分别列出；（2）给出**少样本示例**锚定输出结构；（3）强化日期归一化与“禁止编造”措辞。

### 2.3 测试样本
| 样本 | 特点 |
|------|------|
| sample_meeting_notice.txt | 单类别费用（Regular $500） |
| sample_meeting_notice_multi.txt | 多类别费用（Early Bird/Regular/Student/On-site） |
| sample_meeting_notice_hard.txt | 关键信息缺失（无明确日期/主题/截止日/费用） |

## 三、实验结果

### 3.1 对比表（经 `compare_prompts.py` 真实调用生成）

| 样本 | Prompt版本 | JSON合法 | 字段完整率 | 捕获费用档位数 | 错误信息 |
|------|-----------|----------|------------|----------------|----------|
| 单类别费用样例 | V1 | ✅ | 100% | 1 | — |
| 多类别费用样例 | V1 | ✅ | 100% | 4 | — |
| 缺失信息样例 | V1 | ✅ | 33% | 0 | — |
| 单类别费用样例 | V2 | ✅ | 100% | 1 | — |
| 多类别费用样例 | V2 | ✅ | 100% | 4 | — |
| 缺失信息样例 | V2 | ✅ | 50% | 0 | — |

### 3.2 汇总
- **V1**：JSON 合法率 100%，平均字段完整率 78%，平均捕获费用档位数 1.7。
- **V2**：JSON 合法率 100%，平均字段完整率 83%，平均捕获费用档位数 1.7。

### 3.3 关键观察
- **结构化能力**：两个版本在“多类别费用样例”上均正确捕获全部 4 档费用，说明 `response_format=json_object` + Pydantic 校验能有效约束输出结构。
- **缺失信息处理**：在“缺失信息样例”上，两版都正确将 `date`/`submission_deadline`/`registration_fees` 置为 null，**未出现日期臆造**。
- **差异点**：V1 在缺失样例只填了会议名与地点（33%）；V2 额外把主题推断为 `AI Ethics`（50%）。即 V2 因示例与更丰富的指令，**更倾向于从上下文补全语义字段**，但也带来轻微的“过度推断”风险。

---

## 四、错误分析

1. **过度推断（V2 更明显）**：V2 在会议名含 “AI Ethics” 时，把 `theme` 填为 `AI Ethics`。这源于名称与主题的强相关，**属于语义补全而非原文显式信息**，应视为需要抑制的行为。
2. **样本量有限**：仅 3 个样本，未覆盖“日期格式歧义（如 09/10/2027）”“费用币种混用”“截止日早于会议日”等边界情形，统计结论存在偶然性。
3. **模型随机性**：虽设 `temperature=0`，不同时间调用仍可能有微小差异，需多次重复取稳定结果。

## 五、准确性评价

| 维度 | 评价 |
|------|------|
| JSON 合法性 | 优秀（100%，强制 JSON 模式 + 正则容错） |
| 字段/类型/日期校验 | 优秀（Pydantic 在解析端二次把关） |
| 多类别费用抽取 | 优秀（4/4 档位） |
| 缺失字段保守性 | V1 优于 V2（V1 更不易臆造） |

总体：方案在“结构化抽取 + 程序校验”的主线上表现稳定可靠，可作为后续实验（邮件回复、Function Calling）的基础范式。

## 六、优化建议

1. **融合两版优点**：采用 V2 的“显式结构 + 少样本示例”保证格式对齐，但保留 V1 中“未显式出现的信息禁止补全”的强约束措辞，抑制 theme 等语义补全。
2. **扩充边界测试集**：加入日期歧义、费用区间、多截止日、嵌套表格等样本，并多次重复（≥3 次）取众数，提升评价信度。
3. **后处理校验增强**：对 `submission_deadline` 增加“不得晚于 date”的业务规则校验；对费用金额做合理性范围检查。
4. **可复现性**：固定 `seed`（若接口支持）或记录每次调用的 request_id，便于结果回溯与对比。
5. **密钥与提交规范**：密钥仅存于 `.env` 并由 `.gitignore` 排除，源码、Prompt、测试输入输出、本报告一并提交，避免泄露。
